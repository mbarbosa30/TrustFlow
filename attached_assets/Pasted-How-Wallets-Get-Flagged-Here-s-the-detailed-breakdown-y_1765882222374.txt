How Wallets Get Flagged
Here's the detailed breakdown you can share with your MaxFlow API agent:

Data Collection (Client Side)
When a user interacts with the wallet, we collect a fingerprint containing:

Storage Token: A persistent UUID stored in IndexedDB - survives across sessions until the user clears browser data
User Agent: Full browser/OS string (e.g., "Mozilla/5.0 (iPhone; CPU iPhone OS 17_0)")
Screen: Resolution + pixel ratio (e.g., "390x844@3")
Hardware: CPU cores + device memory (e.g., "8 cores / 8GB RAM")
Timezone: UTC offset (e.g., "UTC-5")
Language: Browser language (e.g., "en-US")
Platform: OS identifier (e.g., "iPhone")
Data Collection (Server Side)
IP Address: Hashed with a static salt for privacy (we store sha256(ip + salt), not raw IPs)
Scoring System
When we detect multiple wallets sharing the same signals, we assign weighted points:

Signal Type	Points	Rationale
Same IP	2 pts	Strong indicator - same network
Same Storage Token	2 pts	Strong indicator - same browser installation
Same User-Agent	2 pts	Strong indicator - exact browser fingerprint
Same Screen	1 pt	Medium - could be common device model
Same Hardware	1 pt	Medium - could be common specs
Same Timezone	0.5 pts	Weak - millions share timezones
Same Language	0.5 pts	Weak - common across regions
Same Platform	0.5 pts	Weak - just OS type
Flagging Threshold
A wallet is flagged when its combined score ≥ 3 points.

This requires at least:

1 strong signal (2 pts) + 2 weak signals (1 pt), OR
3 medium signals (3 pts), OR
Multiple overlapping patterns
Why This Works
Shared networks (cafes, offices) alone won't flag users - they'd need matching devices too
Same device across multiple wallets is definitive evidence of sybil behavior
Cascading detection: if Wallet A shares signals with B, and B shares with C, all three get elevated scores
