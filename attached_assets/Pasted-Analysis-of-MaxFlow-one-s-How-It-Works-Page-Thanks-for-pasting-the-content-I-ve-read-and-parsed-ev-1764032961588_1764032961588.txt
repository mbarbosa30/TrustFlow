Analysis of MaxFlow.one’s “How It Works” Page
Thanks for pasting the content—I’ve read and parsed every line, from the overview to the planned features. This is a solid, transparent technical deep-dive into your system, blending Advogato’s max-flow min-cut heritage with modern web3 twists like epoch-lagged capacities and recursive weighting. It’s concise yet rigorous, positioning MaxFlow as neutral infrastructure (scores as signals, not prescriptions). Below, I’ll summarize the key sections, highlight strengths/weaknesses (ruthlessly self-critiquing where it echoes our earlier loops), and suggest refinements to make it even more powerful for users/integrators.
1. Overview: Dual-Model Scoring (LocalHealth & STS)
	•	Core Idea: Public vouches → verifiable scores via max-flow/min-cut with recursive weighting. LocalHealth (personal, incoming-focused) and STS (community, seed-anchored) as neutral signals for apps to interpret (e.g., credit, governance).
	•	Strengths: Reproducible epochs + Merkle log = full auditability—gold for web3 (no “black box” like EigenTrust). Recursive weighting (capacity = voucherScore / 100) is elegant for propagation, keeping UX simple (binary vouches).
	•	Weaknesses: “Neutral signals” is great philosophy, but the formula (e.g., 0.55Fi + 0.25Ci) feels arbitrary without derivation (why 55% flow? Log-normalization why?). Self-critique: This is the heuristic trap we discussed—tunable, but not graph-pure.
	•	Potential: Tie weights to graph stats (e.g., 55% = avg_degree / max_degree)—makes it adaptive.
2. Vouch-Based Scoring: Binary Input, Recursive Output
	•	Core Idea: Binary vouches weighted by voucher’s LocalHealth (iterative convergence, max 10 rounds, 0.5 threshold). Sybil resistance via accountability (your score influenced by who you vouch for).
	•	Strengths: UX win (yes/no vouch), sophisticated under the hood (recursive = trust chains without complexity). 10-round cap is practical (O(n^2) but bounded).
	•	Weaknesses: Iterative PageRank-style risks convergence loops in dense graphs (threshold 0.5 might not suffice for large n). Self-critique: Echoes our earlier EigenTrust warning—math damping, but in vouch-sparse networks, it could underweight quality (e.g., 1 strong vouch =0.8 capacity, 5 weak=0.6 total).
	•	Potential: Add decay to iterations (round i weight = 0.9^i)—prevents stale loops, boosts recency.
3. Accountability Mechanism: Dilution Penalty
	•	Core Idea: >10 vouches = linear penalty (10% per excess, cap 50%) on redundancy (40% of score). Formula: cutComponent = 40 × (redundancy²) × max(0.5, 1 - 0.1 × excess).
	•	Strengths: Game theory gold—spam costs your own score, enforcing selectivity. Worked example (79.6 → 69.8) is concrete, showing ~12% swing.
	•	Weaknesses: Linear penalty is too gentle (15 vouches =50% cap = -20 pts, but if redundancy high, total -8 pts—still “stings little”). Self-critique: Quadratic scaling (redundancy²) is good for spread, but penalty on redundancy only (40%) means incoming flow (60%) stays untouched—spammers with 1 strong vouch keep high base.
	•	Potential: Exponential penalty (1 - 0.15 ^ excess) for steeper bite (15= ~0.3 factor, -28 pts redundancy = -11 total)—balances without overkill.
4. Graph Construction: Advogato-Style Node-Splitting
	•	Core Idea: Split u into u− → u+ with distance-decayed capacities (c(0)=800, c(1)=240, etc., 30-50% decay). Vouch a+ → b− =1.0; SOURCE → seed_in large; u− → SINK =1.0. Dinic/preflow-push for max-flow/min-cut.
	•	Strengths: Epoch-lagged capacities = genius anti-gaming (prevents dist-manipulation). Decay formula (1.0 / 2^dist) is simple yet effective for local bias.
	•	Weaknesses: Hardcoded decays (30% hop 1, 40% hop 2) are arbitrary—why not uniform geometric (0.7^d)? c(0)=800 is “large” but arbitrary for SOURCE. Self-critique: Node-splitting is classic Advogato, but in sparse graphs, SINK=1.0 makes min-cut trivial (1 unit = accepted), under-rewarding redundancy.
	•	Potential: Dynamic decay λ = 0.7 ^ d (tunable per community)—adapts to network (dense = steeper λ).
5. Personal Networks (Ego Score): Pure Option 2 Iterative
	•	Core Idea: Recursive weighting (capacity = voucherScore / 100), iterative convergence. EgoScore = 60 × (flowScore²) + 40 × (redundancy²) × vouchQuality. Flow = directFlow /5 (healthy vouch count), Residual = directFlow / vouchCount.
	•	Strengths: Binary UX + recursive = elegant Sybil resistance. Quadratic scaling (²) for spread—good for power-law rep. No co-seeds = accessible for solo users.
	•	Weaknesses: /5 for flowScore is magic (why 5?); redundancy² on what (ego size/density heuristic?). Iterative 10 rounds risks slow convergence in cycles. Self-critique: Quadratic is nice for spread, but vouchQuality undefined (placeholder?). Residual = flow / vouchCount ignores edge strength—weak vouchers pull average down too little.
	•	Potential: FlowScore = log(1 + directFlow) / log(1 + global_avg_flow)—dynamic, no magic.
6. KUDOS: Pure Rewards Layer (No Scoring Influence)
	•	Core Idea: KUDOS from LocalHealth claims only—no back-influence on scores (neutrality).
	•	Strengths: Keeps scoring pure—rewards don’t game the graph. One-way = simple, anti-loop.
	•	Weaknesses: If KUDOS is “trust currency,” excluding it from boosts feels underpowered (no economic nudge). Self-critique: Neutrality is noble, but in “investment” lens, KUDOS as “co-investment” (small boost) could catalyze without corrupting.
	•	Potential: Optional community toggle “KUDOS boost enabled” (1 + min(0.5, kudos /1000))—neutral core, opt-in economics.
7. Acceptance & Tiers: Neutral Thresholds
	•	Core Idea: Flow ≥0.5 AND min-cut ≥2 for acceptance. Tiers: Connected ≥40, Verified ≥60, Trusted ≥80 + min-cut ≥3 + stability ≥0.8.
	•	Strengths: Neutral labels + thresholds = actionable (apps interpret). Min-cut ≥2 = basic redundancy.
	•	Weaknesses: 0.5 flow threshold arbitrary (why not 1.0?); stability ≥0.8 undefined (Δi from edge removal?). Self-critique: Tiers are interpretive, but thresholds feel like “neutral with bias”—why 40/60/80?
	•	Potential: Thresholds as percentiles (40th = Connected)—data-driven, adaptive.
8. STS: Standardized 0-100 (Log-Normalized Components)
	•	Core Idea: STSi = 100 × (0.55Fi + 0.25Ci + 0.05Si + 0.10Di + 0.05PRi), with log-normalized percentiles (F95, C95).
	•	Strengths: Log-normal for power-law rep, percentiles for comparability. Components cover flow/cut/stability/depth/PageRank—comprehensive.
	•	Weaknesses: Weights (0.55 flow, 0.25 cut) arbitrary (why 55%?); log(1+fi) assumes small fi, but high-flow users skew. Self-critique: 5 components = overfit; why not 3 (flow, cut, stability)?
	•	Potential: Weights from graph entropy (e.g., 0.55 = flow variance / total)—self-tuning.
9. Stability & Diversity + Node Caps
	•	Core Idea: Stability = 1 - min(1, Δi) (edge removal drop); Diversity = disjoint regions via min-cut; Node caps c(d) decayed (800 at 0, 24 at 4+).
	•	Strengths: Stability local recompute = efficient; caps prevent spam dilution—epoch-lagged = anti-manipulation genius.
	•	Weaknesses: Δi “worst relative drop” is compute-heavy (all-edge removal); diversity “multiple disjoint regions” vague (how measured?). c(0)=800 arbitrary. Self-critique: Caps are good, but 30% decay hop1, 40% hop2 feels tuned, not derived.
	•	Potential: Stability as 1 - (max_edge_flow / total_flow)—single run.
10. Public Vouches, Verifiability, Seed Scoring
	•	Core Idea: Public Merkle log for vouches; attestations with roots/signatures. Seed Score (Ss) = 0.35 predictive + 0.30 downstream + 0.20 diversity + 0.15 centralization penalty; SOURCE cap = base * (0.7 + 0.6 Ss).
	•	Strengths: Public = audit gold; seed scoring self-corrects (good seeds amplify, bad throttle). Coverage ≥2 = basic resilience.
	•	Weaknesses: Ss weights arbitrary (35% predictive?); “distinct communities” vague (how defined?). Self-critique: Feedback loop is cool, but 0.6 Ss multiplier risks instability (bad seeds throttle too fast).
	•	Potential: Ss as PageRank of seeds—graph-derived.
Overall Assessment: Strengths, Weaknesses, Suggestions
	•	Strengths: Neutrality shines (scores as signals, apps interpret); accountability (dilution) is killer anti-Sybil; public/Merkle = web3-native; epoch-lagged caps = elegant security.
	•	Weaknesses: Arbitrary weights/decays/thresholds (the heuristic loop); iterative convergence risks cycles; STS over-complicated (5 components); KUDOS “pure rewards” underuses economic nudge.
	•	Suggestions:
	◦	Derive weights (e.g., flow % = flow_variance / total_var)—data-driven.
	◦	Add net flow nudge ( +1% for positive, as we discussed).
	◦	For ego score: Quadratic exp good for spread, but /5 healthy vouch count = magic—make /global_avg_vouches.
	◦	Planned features (vertex-disjoint, dust-flow) = solid roadmap—prioritize for vulnerable communities.
This is a strong blueprint—neutral, verifiable, accountable. For microcredit, STS as “credit score” (80+ = trusted tier) is killer. What’s your priority: Tune STS weights, or prototype ego code?
