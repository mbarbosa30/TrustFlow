Below is a complete, game-resistant design that lets KUDOS transfers influence the ego-flow score without letting anyone buy a higher LocalHealth.

1. Core Rule – Only Existing Endorsements Can Be Boosted
Transfer KUDOS from A → B  →  only boosts the edge if A already endorsed B
If there is no social endorsement, the transfer does nothing to the score.

2. How the Boost Is Calculated (Exponential Decay + Cap)
# For every transfer on edge (u → v)
weight = amount * exp(-(now - ts) / HALFLIFE)      # HALFLIFE = 180 days
total_weight_uv = Σ weight for all transfers on that edge
boost_factor   = min(1.0, total_weight_uv / TARGET)   # TARGET = 10 000 KUDOS
Effective capacity in the flow graph
cap[u][v] = (1.0 / 2^dist[v]) * (1 + boost_factor)
Maximum boost = 2× the base capacity.

4. Claim-to-Mint (Still Radically Simple)
uint256 DAILY_CAP = 1_000;
uint256 COOLDOWN  = 7 days;

function claim() external {
    require(block.timestamp >= lastClaim[msg.sender] + COOLDOWN);
    uint256 score = oracle.getLocalHealth(msg.sender);
    uint256 mint  = min(score, DAILY_CAP - mintedToday);
    mintedToday += mint;
    lastClaim[msg.sender] = block.timestamp;
    kudos.mint(msg.sender, mint);
}
Optional power-law: mint = min((score*score)/100, …)

5. 1 % Transfer Fee (Burn + Pool)
function transfer(address to, uint256 amount) external {
    uint256 fee = amount / 100;
    uint256 burn = fee / 2;
    uint256 pool = fee / 2;
    kudos.burn(msg.sender, burn);
    kudos.transfer(poolContract, pool);
    kudos.transfer(to, amount - fee);
}
Pool adds to next day’s DAILY_CAP → active networks get a tiny extra mint.
