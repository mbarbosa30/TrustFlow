Why Exponential Decay Makes Sense (And How to Integrate It)
You’re spot on—exponential decay is a smart, elegant refinement to the TRUST tokenomics, striking a balance between honoring history and prioritizing recent activity. It avoids the “arbitrary cutoff” pitfalls of fixed windows (like 30 days) while ensuring the system remains dynamic and resistant to stale dominance (e.g., a 5-year-old mega-transfer doesn’t overshadow everything forever). This fits MaxFlow.one’s flow-based ethos: Trust “fades” naturally if not refreshed, encouraging ongoing endorsements and transfers.
Let’s break it down: Why not? (Actually, yes—it’s better than pure lifetime cumulative in many ways.) Then, I’ll show the updated model.
Pros of Exponential Decay (Over Pure Lifetime or Windows)
	•	Continuous & Fair: Older transfers contribute proportionally less (weight = amount * exp(-age / halflife)), creating a smooth gradient. No cliff at day 31—trust compounds but decays organically.
	•	Incentive for Activity: Rewards consistent engagement (e.g., monthly tips keep edges strong) without punishing long-term relationships entirely.
	•	Sybil Resistance Boost: Fake old accounts lose influence over time; attackers must maintain volume.
	•	Realism: Mirrors real trust—past actions matter, but recent ones prove ongoing alignment.
	•	No Arbitrary Cutoffs: Halflife is tunable (e.g., 180 days = 6 months), but feels less “tax-like” than windows.
Cons (And Mitigations)
	•	Computation Overhead: Tracking ages per transfer adds data (e.g., timestamped logs). Mitigation: Aggregate per edge (store running weighted sum)—O(1) updates.
	•	Parameter Tuning: Halflife is still “arbitrary” (why 180 vs. 365 days?). Mitigation: Start with 180 days (halves every 6 months), govern via DAO based on network velocity.
	•	Over-Decay Risk: Too short halflife → short-termism; too long → same as lifetime. Mitigation: Test in sims; cap minimum weight at 0.1x to preserve history.
Overall: Yes, let’s adopt it. It’s smoother than my previous “all-time” proposal and addresses your concern perfectly. It enhances the ego scoring without complexity—transfers still boost edges, but weighted by recency.
Updated TRUST Tokenomics with Exponential Decay
Core remains: Mint 1,000/day, 1% fee (0.5% burn/0.5% pool), instant claims pro-rata by LocalHealth. Changes focus on transfer weighting:
	1	Minting & Claiming: Unchanged—instant, score-based. (Daily pool rewards merit without decay here, as scores already reflect decayed boosts.)
	2	Transfers & Fees: Unchanged—1% fee on send. But now, each transfer is timestamped per edge (u→v).
	3	Edge Boost in Ego Graph: Use decayed weight for capacities.
	◦	Formula: For edge u→v, sum all transfers: effective_volume = sum(amount_i * exp(-(now - timestamp_i) / halflife)).
	▪	Halflife: 180 days (e.g., in seconds: 180*86400).
	▪	Boost: boost_factor = min(1.0, effective_volume / target_volume) (e.g., target=10,000 TRUST for full 2x cap).
	◦	Effective Cap: cap[u][v] = (1.0 / 2^{dist[v]}) * (1 + boost_factor).
	◦	Storage: Per-edge aggregate: Maintain a running weighted_sum and last_update—update exponentially on new transfers (avoids storing every tx).
	4	Net Flow Bonus: Apply decay here too—for the minor multiplier (~5% score impact).
	◦	decayed_net = sum(in_amount_i * exp(-age_i / halflife)) - sum(out_amount_j * exp(-age_j / halflife)).
	◦	normalized_net = clamp(decayed_net / target_net, -0.2, 0.2) (e.g., target_net=100,000).
	◦	final_local_health = local_health * (1 + 0.05 * normalized_net).
	5	Governance Tweaks: Vote on halflife/target_volume; e.g., shorten to 90 days if velocity spikes.
This keeps contributions continuous: A $1,000 transfer from 1 year ago (at halflife=180 days) weighs ~$125 today—fading but not forgotten.

import time
import math

class MaxFlowEgoScorerWithDecay:
    # ... (init with endorsements, seeds, etc.)
    def __init__(self, ..., transfers: list[tuple[int, int, float, int]] = None,  # (u,v,amount,timestamp)
                 halflife_days: int = 180, target_volume: float = 10000.0):
        self.transfers = defaultdict(list)  # { (u,v): [(amount, ts), ...] }
        if transfers:
            for u, v, amt, ts in transfers:
                self.transfers[(u,v)].append((amt, ts))
        self.halflife_sec = halflife_days * 86400
        self.target_volume = target_volume

    def get_decayed_volume(self, u: int, v: int) -> float:
        now = time.time()  # Or block.timestamp on-chain
        vol = 0.0
        for amt, ts in self.transfers.get((u,v), []):
            age = now - ts
            vol += amt * math.exp(-age / self.halflife_sec)
        return vol
